CORE

Concepts to learn first

Read these before drilling into any page — they explain language used everywhere else in the platform.

Engine modes

The trading engine has 7 modes, each with different signal logic and risk profile. The Live Trader picker exposes optimized / tactical / tactical-smart / adaptive; the four base signal modes (conservative / moderate / aggressive + optimized) are reachable via adaptive's regime classifier.

  • conservative — small positions, strict filters, swing horizon
  • moderate — default starting mode, balanced filters
  • optimized — uses GA-tuned signal params (EMA fast/slow, RSI thresholds) from the optimizer
  • aggressive — looser filters, more positions, momentum-tilted
  • tactical — market-wide on/off (SPY-driven). Full in / full out, no per-symbol gates
  • tactical-smart — scored basket with active swapping. Re-ranks weekly
  • adaptive — reads market regime (VIX + SPY/SMA50) at every scan and runs as conservative / moderate / optimized / aggressive underneath. Status banner shows the effective mode. Never auto-selects tactical or tactical-smart.
  • Intraday mode was removed in v3.1 — the engine no longer offers a 5-min-bar mode.

Risk profile (single source of truth)

Risk settings live on the Trader page. They drive: position sizing, max position count, exposure caps, daily-loss halt, sector exposure cap, earnings blackout, wash-sale protection, PDT protection, and consecutive-loss halt. Settings page display preferences are separate from risk.

Signals vs watchlist vs screener

  • Watchlist — your manual list of symbols. Multiple named lists per user. Default list is what every widget defaults to.
  • Screener — server-side market scanner. Runs over the full S&P 500 every 5 minutes. Pushes high-confidence BUY/STRONG_BUY signals to the engine.
  • Signal — output of the analyzer (BUY / STRONG_BUY / HOLD / SELL / STRONG_SELL) with a confidence 0–1. Combined technical + sentiment + options-flow + analyst + AI scoring.

Broker as source of truth

Open positions and account equity come from Alpaca, not the database. The engine syncs its in-memory position map from broker data on every scan. If the broker is unreachable, the dashboard falls back to a cached snapshot tagged with how stale it is.

Engine-gated operations

While the engine is running, two operations are refused (API returns 409 ENGINE_RUNNING, UI shows a yellow banner): manual orders via /trade/[symbol], and broker connection switching. Stop the engine first. This prevents the in-memory position map from drifting from the broker.

Position detail sheet

Click any row in Open Positions on the Trader page (or anywhere a <SymbolLink> appears) to slide in a detail drawer with entry/current/P&L, recent signal history, and quick actions (View Chart, Manual Trade, Close Position).

P&L $/% toggle

Every monetary display respects your preference (Dollar / Percent / Both). Toggle from the sidebar P&L button or Settings → Display Preferences. Setting is per-device (localStorage), syncs across tabs via the storage event.

Display preferences

Settings → Display Preferences card covers: P&L format, time format (12h/24h), color-blind palette (Wong blue/orange instead of green/red), default landing page after login, daily-digest email opt-in. All localStorage-backed, cross-tab synced.

Themes (5 options)

Theme picker in the sidebar footer + landing nav lets you choose between Light (default — white surfaces, emerald accent), Dark (emerald-tinted near-black), Coral (warm peach surfaces, coral accent), Light Blue (sky-tinted, blue accent), and Gray (true neutral grays, emerald accent retained). Each theme is a single class on <html>; trading semantics (bullish/bearish/warning) stay universal red/green across all themes so P&L is recognizable. Preference persists in sentinel-theme localStorage key + updates the PWA theme-color meta tag.

Focus mode + chart fullscreen

Focus mode (Analysis page header) collapses the dashboard sidebar to maximize the research workspace. Persists per-device; auto-cleans on page unmount so the sidebar isn't globally hidden when navigating away.

Chart fullscreen (Maximize icon in chart toolbars on Analysis, Replay, and Backtest) expands a single chart to fill the viewport. Esc or the Exit button to close. Works for both lightweight-charts views and the embedded TradingView widget.

Smart back button

Detail pages (Trade ticket, Articles, Messages, Support tickets, Forum threads, Posts) use <SmartBackButton fallbackHref> for their back arrow. When there's same-origin browser history, it pops the stack — returning the user to wherever they came from (Cmd+K jump, notification, feed link). Direct-link arrivals (bookmarks, email) fall through to the explicit href.

Symbol quick-info drawer

Ticker rows on Unusual Activity (and elsewhere) open a slide-out preview drawer (<SymbolPreviewSheet>) with price + change + signal + RSI + volume + sector + escape hatches (View Analysis / Trade / Add to Watchlist). Quicker than navigating away.

AI is on Groq

Every AI feature (Insights, Quick Insight widget, hybrid signal scoring, sentiment, filings chat, market digest, AI chat, the Recent Trades AI ✨ button) runs on Groq (llama-3.3-70b-versatile). Admins rotate the key at System Configuration — no SSH required. AI keys are server-wide.

Hash-chained audit log

Every privileged action (logins, order placements, halts, config changes, role changes) writes an append-only row whose hash links to the previous row. Audit Log page has a "Verify chain" button that walks the entire log and reports any break. Tamper-evident.

HOME

Dashboard Home

Home (command center) /dashboard

Configurable command center with resizable widgets. Set up one or more named layouts for different contexts (e.g. "Pre-market", "Live trading", "End-of-day review").

Key UI surfaces

  • Layout switcher (top right) — dropdown of saved layouts. Switch instantly without leaving the page.
  • Widget grid — resizable cells, drag to reorder, resize handle to change size (sm/md/lg/full).
  • Add widget button — picks from the registry (15 widgets, see below).
  • Save layout — name and save the current arrangement. Default layout loads on every fresh login.

Buttons & controls

  • Layout dropdown — Switch, Rename, Delete, Set as default. Refuses to delete the last remaining layout.
  • Widget close (×) — removes from the current layout. Doesn't delete the underlying data.
  • Widget resize handle — bottom-right corner of each widget. Drag to change size class.
Gotcha: layouts are per-user but shared across devices. Resizing a widget on mobile changes its size on desktop too.

See Dashboard widgets below for what each widget shows.

Analysis

Analysis (technical cockpit)/dashboard/analysis

Chart + signal evaluation for a single symbol. The deepest research surface for one ticker at a time. Chart on top spanning the full width (~48vh), three panels stacked underneath (watchlist / intelligence tabs / signal details) — layout shipped 2026-05-13 after iterating away from the older 3-column-with-chart-in-the-middle design.

Key UI surfaces

  • Chart row (top) — Engine view / TradingView toggle + fullscreen button. Height clamps between 340–580px depending on viewport so the panels below stay visible without scroll.
  • Left panel (row 2) — your watchlist (with the active-list switcher dropdown + ★ Make Default affordance to promote any list without leaving the page) + add-symbol form + Recently Viewed list.
  • Center panel (row 2) — Intelligence tabs (Indicators / Fundamentals / News / Insiders / Calls / Reddit / Backtest).
  • Right panel (row 2) — Signal details: SignalBadge + confidence bar + price + Signal DNA + indicators (3-col tile grid: RSI / MACD / EMA) + risk (3-col tile grid: Stop / Target / R:R) + hybrid layers + collapsible What-If simulator + side-by-side Simulate/Execute buttons + collapsible Market Context (analyst consensus, insider activity, social buzz, peer stocks).
  • Chart toggle — switch between "Engine view" (lightweight-charts with BUY/SELL markers + earnings markers) and "TradingView Advanced Chart" (full drawing tools).
  • Reddit tab — recent Reddit posts mentioning the symbol across the admin-managed subreddit list (default: r/stocks, r/investing, r/SecurityAnalysis, r/wallstreetbets). Each post shows subreddit pill, time-ago, sentiment chip, and link-out. RSS-sourced (Reddit blocks JSON from datacenter IPs); admins can add/remove subreddits at /dashboard/admin → Reddit Feed Sources.
  • 5-timeframe snapshot — 1m / 5m / 15m / 1h / 1d signals side-by-side.

Buttons & controls

  • Focus mode (page header) — toggles a class on <html> that hides the dashboard sidebar to maximize the research workspace. Persists across visits via localStorage. Auto-cleans the class on page unmount.
  • Maximize (chart toolbar) — expands the active chart to fill the viewport. Esc or the Exit button to close. Works for both Engine view and TradingView.
  • Trade button (sidebar) — jumps to /trade/{SYM} with the symbol pre-filled.
  • Refresh — re-runs the analyzer with fresh bars. Bypasses cache.
  • Chart mode persists per-device in sentinel-chart-mode localStorage key.
  • Expandable sections (right panel) — "What-If Simulation" and "Market Context" both collapsed by default to keep the panel compact; click the chevron header to expand.
Gotcha: deep links like ?symbol=HPE work — used by Cmd+K, congress page, performance attribution, and every <SymbolLink> in the app. The Signals panel that used to live on the left column was removed (2026-05-13) — get screener signals on /dashboard/screener.

Screener & Trader

Screener/dashboard/screener

Server-side market scanner. Runs over the full S&P 500, returns symbols matching active filters with their current signal.

Key UI surfaces

  • Filter chips — toggle signal type (STRONG_BUY only / BUY+/etc), min confidence, RSI bands, volume multipliers.
  • Results table — symbol, signal, confidence, RSI, volume mult, change %.
  • Scan status — "Last scanned X ago" or "Scan in progress, started X ago" if a fresh scan is running.

Buttons & controls

  • Scan Market — triggers a fresh full-universe scan. Concurrent triggers return the in-flight result instead of re-scanning.
Shared resource: the screener cache is global across all users — not per-user. One scan serves everyone. Filters are applied client-side from the cached scan output.
Live Trader/dashboard/trader

Engine controls + live positions + risk profile. The most important page in Beacontry.

Key UI surfaces

  • Status banner — engine running/stopped, mode, current P&L. Red LIVE badge when running on a live connection.
  • Headline P&L cards — Today $, Today %, Unrealized $, Unrealized %. Format honors your P&L preference.
  • Open Positions table — Symbol, Entry, Current, P&L $, P&L %, Trail Stop, Signal. Click row → position detail sheet.
  • Open Orders table — pending/working orders from the broker.
  • Recent Trades list — date, symbol, side, qty, price, P&L. Each row has an AI ✨ button (see below).
  • Signals list — latest from the screener or manual triggers.
  • Risk Overrides panel — read-only by default. Click Settings icon to edit. Source of truth for max position size, daily loss halt, sector cap, earnings blackout, MTM election, consecutive-loss threshold. Each field has a ? info icon next to the label — hover for a one-line explanation of the concept and typical values (added 2026-05-13).
  • PDT warning panel (yellow) — appears when account equity < $25k. Shows current day-trade count.
  • Tax Status card — MTM election checkbox. Drives wash-sale protection on/off.
  • Tax callouts — harvestable unrealized losses surfaced inline.

Buttons & controls

  • Start / Stop — toggles the engine. Refuses to start on a live connection unless ALLOW_LIVE_TRADING=1 is set in env AND the user has live trading enabled.
  • Mode selector — pick optimized / tactical / tactical-smart / adaptive. (The four base signal modes — conservative / moderate / optimized / aggressive — are reachable only via adaptive's regime classifier.)
  • Halt — manual halt. Closes all positions at market, refuses new orders for the day.
  • Flatten all — sells all positions immediately at market.
  • AI ✨ (each trade row) — generates a Groq-powered 1-2 sentence plain-English summary of the trade (entry reason → hold period → exit). Cached on the row after first click. Label flips to ↻ once cached. Costs ~$0.0001 per click.
Engine-gated: while running, manual orders and broker switching are refused with a 409 ENGINE_RUNNING response. Stop the engine first.
Strategies/dashboard/strategies

Library of saved strategies — each is a named bundle of 8 parameters (EMA fast/slow, RSI thresholds, stop %, take profit %, trail %, hold period).

Buttons & controls

  • Create — opens the Strategy Builder wizard.
  • Edit — adjust params, rename, re-save.
  • Backtest — runs the current strategy against historical data and jumps to the result.
  • Compare — appears when 2+ saved. Multi-select up to 5, opens /dashboard/backtest/compare.
  • Deploy — marks the strategy as the engine's active config for the user's account.
Strategy Builder/dashboard/strategy-builder

Form wizard for tuning the 8 strategy parameters. Visual feedback on what each knob does. Recommended for users uncomfortable with the bare parameter list.

Backtest/dashboard/backtest

Run a single strategy against historical data — see equity curve, win rate, drawdown, Sharpe/Sortino/Calmar/MAR.

Buttons & controls

  • Symbol — single symbol or a watchlist.
  • Strategy — pick one of the 7 engine modes, a saved strategy, custom (manual params), or auto (optimizer-picked).
  • Date range — days back or startDate/endDate mode. Daily bars only (Yahoo intraday only retains ~60 days).
  • Stop Loss / Trail Stop / Take Profit / Hold Period — each has a ? info icon explaining the concept and typical values (added 2026-05-13).
  • Auto-tune (⚡) button — now has a hover tooltip explaining the ATR-based tuning logic.
  • Run — kicks off the backtest. Equity curve animates in as it processes.
Long-range 5m backtests aren't possible without a paid intraday data feed. Daily bars are the supported window.
Backtest Compare/dashboard/backtest/compare?ids=...

Side-by-side comparison of up to 5 saved strategies — stats columns + an overlaid equity curve normalized to start = 100. URL-driven so links are shareable.

Mode Compare/dashboard/backtest/mode-compare?symbol=AAPL

Runs all 6 comparable engine modes (conservative through adaptive) against the same symbol + date-range in parallel. See empirically whether adaptive's regime-switching beats sticking with one mode.

Key UI surfaces

  • Symbol input + days back selector (defaults to 5 years).
  • Stats table: rows = modes, columns = Return / Win Rate / Trades / Max DD / Sharpe / Sortino / Calmar / MAR.
  • Equity-curve overlay: 6 normalized-to-100 lines. Adaptive draws thicker so it stands out from the base modes.
  • Adaptive mode timeline (when adaptive succeeds): chronological strip showing which underlying mode adaptive was running at each regime switch.

Gotchas

  • tactical-smart's active basket-swap logic doesn't translate to a daily-bar backtest comparison, so the comparison runs optimized + tactical + adaptive. (Intraday mode was removed in v3.1.)
  • Adaptive requires SPY + ^VIX bars for the date range. If the provider can't supply them, the adaptive row shows an error and the other 5 modes still render.
  • Results cached 5 minutes per (symbol, days) tuple — daily bars don't change intraday so re-running with same params returns cached.
Replay/dashboard/replay

Optimizer/dashboard/optimizer

Genetic algorithm optimization across the 8 strategy parameters. Train on 5 years of S&P 500 data, walk-forward validate.

Key UI surfaces

  • Convergence chart — fitness vs generation.
  • Results table — top-N evolved strategies with returns, drawdown, walk-forward stability.

Buttons & controls

  • Population — 10–100 strategies per generation.
  • Generations — 5–100 evolution rounds.
  • Train/Test split — 40–80% walk-forward.
  • Universe — Top 50 vs Full S&P 500.
  • Run — kicks off the GA. Admin-only.
Admin-only: running optimization is gated to role=admin. Results are shared globally though — the "optimized" engine mode picks up the latest stable params for every user.

Manual Trade Ticket/dashboard/trade/[symbol]

Place an order outside the engine. BUY/SELL × market/limit/stop/stop-limit × day/gtc/ioc/fok. Supports bracket orders and fractional shares.

Key UI surfaces

  • Symbol header — current price + intraday change.
  • Side toggle — BUY / SELL.
  • Order type — Market / Limit / Stop / Stop-Limit. Each option in the dropdown carries a one-line plain-English explanation, and the field label has a ? info icon (added 2026-05-13).
  • TIF — Day / GTC / IOC / FOK. Same hover-help treatment as Order Type.
  • Limit / Stop price fields — show inline help explaining what each price means and when to set above vs below current.
  • Bracket toggle (BUY-only, share-mode only) — atomic entry + stop-loss + take-profit.
  • Notional toggle (Alpaca only) — dollar-based buys, fractional shares. Market + day/ioc only.

Buttons & controls

  • Place order — confirms (with extra LIVE confirmation if the active connection is live). Submits to broker.
Engine-gated: refused while the engine is running. UI banner + API 409. Stop the engine to place manual orders, or use a different broker connection that the engine isn't using.
J

Journal

Journal (v2)/dashboard/journal

Trade-by-trade notes, tags, behavioral feedback. The "what was I thinking" record. Journal v2 (2026-05-13) replaces the old blank-canvas approach with auto-stubs, daily prompts, categorized tagging, and AI weekly review.

Entry types

  • Manual — you wrote it. Default for new entries.
  • Trade stub — auto-generated when a trade fills. Pre-fills symbol, P&L, signal context. You add the WHY.
  • Pre-market prompt — daily 8:30 ET stub with 4 questions (plan, bias, watchlist, what you're NOT trading).
  • Post-market prompt — daily 4:30 ET stub with 4 reflection questions.
  • Weekly review — AI-generated Sunday recap (Week in numbers / What worked / What didn't / Pattern across the week / One question for next week). Costs ~$0.005/user/week on Groq.

Tagging

  • 30 tags across 4 categories: Emotion (discipline, patience, confidence, fear, greed, FOMO, revenge, boredom), Strategy (breakout, mean-rev, trend, swing, intraday, news, earnings, technical), Execution (followed plan, perfect, early exit, late entry, size too big/small, stop too tight/wide), Outcome (win, loss, breakeven, stopped out, full target, partial).
  • Tag IDs are namespaced (emotion_*, strat_*, etc) so the patterns API can group cheaply.
  • Entry-card badges color-coded by category.

Behavioral patterns

  • Quiet card at the top of the journal showing per-tag win rate vs your baseline. Tag has to hit n=5 to surface.
  • Bullish-colored chip if >+5pp above baseline, bearish if >-5pp below.
  • Click a chip to filter entries to that tag.
  • Renders nothing when no tag has enough data — quiet by design.

Cross-feature linking

  • ?symbol=AAPL URL param filters to that symbol on mount. Used by Performance attribution rows.
  • ?date=2026-05-13 URL param filters to that date (matches both prompt_date and created_at::date). Used by P&L Calendar day modal.
  • Auto-trade entries get an "Open chart →" link to /dashboard/analysis.

UI polish

  • Unfilled stubs/prompts sort to the top of the entry list with an accent border + "Needs review" badge + italic muted notes.
  • Per-type icon + label badge on each entry.
  • Edit/delete buttons inline.

Sentiment-tagged financial headlines (general + per-symbol). Each article carries a ▲ Bullish / ▼ Bearish / ● Neutral badge from keyword scoring.

Not the hybrid sentiment layer. The badge is fast keyword-based directional hint, not the deeper Finnhub-sourced sentiment that feeds signal math.

Bullish/bearish percentage by symbol from Finnhub's social-sentiment endpoint, with trend arrows over time.

Articles/dashboard/articles

Curated longer-form trading + finance articles with reading progress tracking. As of 2026-05-13, auto-populated daily by the market-digest cron — each day's AI-generated digest also lands here as a free article with slug market-digest-{YYYY-MM-DD}.

Categories

  • Daily Digest — auto-populated, one per trading day.
  • Manual — admins write/upload longer pieces via the admin tools (future expansion).
Filings/dashboard/filings

SEC filings (10-K, 10-Q, 8-K, S-1, etc.) by symbol from Finnhub. Click filing → AI-summarized via Groq.

Insights/dashboard/insights

AI-powered "why is this stock moving today" generated from current quote + recent news. Cached 5 minutes per symbol. Runs on Groq.

Congress/dashboard/congress

Federal Periodic Transaction Reports pulled directly from the official sources — House Clerk bulk PTR archive (disclosures-clerk.house.gov) and Senate efdsearch — with daily refresh. Members of Congress are required to report trades within 45 days. Beacontry surfaces them filterable by ticker, member name, chamber, direction. Free across all tiers — the same data competitors like Quiver charge $10/mo for.

Buttons & controls

  • Ticker filter — server-side query.
  • Member name search — client-side filter.
  • Chamber / Direction — radio toggles.

Hash-chained log of every privileged action. Tamper-evident. Searchable.

Key UI surfaces

  • Filter — by user, action, date range, resource type.
  • Detail row — actor, IP (from X-Forwarded-For), user agent, metadata blob, prev_hash, hash.

Buttons & controls

  • Verify chain — walks every row, recomputes each hash, reports first break (or "intact"). Takes ~2s per 100k rows.
If verify reports a break, stop trading immediately. The chain breaking means either someone deleted/modified rows, or there's a code bug. Either way, the audit trail is no longer trusted.
System Configuration/dashboard/admin/system-config

Rotate server-wide encrypted API keys without SSH. Currently supports Groq, Finnhub, Anthropic.

Key UI surfaces

  • One row per known key with last-4-char mask + source badge (DB / ENV fallback / Not set).
  • "Updated by … X ago" metadata per row.

Buttons & controls

  • Replace button → opens a paste modal.
  • Test before save — hits the live provider with a 1-token ping using the candidate key. Returns ✓ or specific error. Value is NOT persisted.
  • Save — encrypts (AES-256-GCM), upserts into the system_config table, invalidates the 60s in-memory cache, writes a hash-chained SYSTEM_CONFIG_UPDATED audit row (metadata records key name + actor + whether prior value existed, never the value itself).
Server-wide: these keys are shared by every user. One Groq key powers AI for the whole deployment. Per-user overrides are a deferred design — see docs/future-ideas.md.
Finnhub caveat: the Finnhub client reads its key once at process boot. Rotating FINNHUB_API_KEY via this UI requires an app restart for the trading engine + per-symbol routes to pick up the new value. The LLM path is fully async and refreshes within the 60s cache window.

GLOSSARY

Internal terms

Beacontry-specific or trading-specific terms that appear throughout the UI and these docs.

Boot equity

Equity captured when the engine starts. Used as the baseline for the 50% equity-collapse tripwire. Re-snapshots at every new trading day so the tripwire stays calibrated as the account grows.

Position map

The engine's in-memory map of symbol → TrackedPosition. Updated from broker on every scan (syncPositionMapFromBroker). The dashboard always reads this, but the broker is the source of truth — if they ever diverge, the broker wins.

Hybrid signal

The final signal that flows from analyzer → engine. Combines: technical analysis (EMA crosses, RSI, MACD, volume), sentiment (Finnhub social), options flow (unusual call/put ratios), analyst recommendations, AI scoring (Groq adjusts confidence ±0.20). Each layer can be turned on/off per pipeline.

Screener

Server-side market scanner. Scans the full S&P 500 every 5 minutes, returns symbols matching active filters. Pure technical — does NOT run sentiment / options / analyst layers (those serialize through Finnhub's rate limit and would make scans 15-45 min instead of 30-60s). The engine re-applies hybrid layers when it processes screener-pushed signals.

Optimizer

Genetic algorithm that evolves the 8 strategy parameters against 5 years of S&P 500 history. Walk-forward validated. Output feeds the optimized engine mode. Admin-only to run; results are shared globally.

MTM (§475(f) Mark-to-Market)

An IRS election that lets active traders (1) treat trading gains/losses as ordinary income instead of capital gains, and (2) be exempt from wash-sale rules. Election must be made at year-start. Beacontry self-attestation drives wash-sale protection on/off — DOES NOT file or validate the election. Talk to a CPA.

PDT (Pattern Day Trader)

FINRA rule: if equity < $25k AND ≥4 day-trades in 5 business days, the broker locks the account. Beacontry auto-detects the equity threshold and blocks new BUYs at 3+ daytrades (one shy of the limit). SELLs are always allowed — exits override PDT.

Wash sale

IRS §1091: selling at a loss and buying a "substantially identical" security within 30 days disallows the loss for tax purposes. Beacontry's wash-sale protection blocks BUYs on any symbol with a losing exit in the last 31 calendar days. Symbol-level, not lot-level — over-conservative but simpler. Disabled when MTM is elected.

Trailing stop (dynamic)

Stop-loss that tightens exponentially as profit grows. At entry: ~10% trail (disaster stop). At 30% profit: ~3.7% trail (locks in ~26%). At 50% profit: ~2.4% trail (locks in ~48%). Beacontry pushes the actual stop to the broker on every scan so it's enforced even if Beacontry crashes.

Sector exposure cap

Risk-profile setting that refuses BUYs that would push any sector over cap × equity. E.g. cap=0.25 means no more than 25% of equity in any single sector. Calculated from live broker position values.

Earnings blackout

Risk-profile setting that skips BUYs within N trading days of a symbol's earnings release. Reduces gap risk. Default: disabled.

Hash chain (audit log)

Every audit row's hash includes the previous row's hash. To tamper with a single row, you'd need to recompute every subsequent row's hash. Verify chain button walks the entire log in id order, recomputes each hash, reports first mismatch.

Hybrid signal vs technical signal

The screener emits pure technical signals (fast scans). The engine re-runs analysis with hybrid layers (sentiment, options flow, analyst, AI scoring) before deciding whether to actually buy. Both use the same analyzeBars() core — the engine just layers more context on top.

Engine-gated

Operations refused while the engine is running, returning 409 ENGINE_RUNNING: manual order placement, broker connection switching. Prevents the in-memory position map from drifting from the broker. Stop the engine first.
