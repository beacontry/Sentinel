2026-05-26

Incident response marathon (PRs 1-17)

Triggered by a user observation that tactical-smart was outperforming optimized on the live account. Expanded into a full audit pass that surfaced 2 P0 + several P1 bugs in the engine + GA, plus the strategy-frame gap between live and backtest. Closed both. Net result: optimized mode now competes with tactical-smart on capability while retaining its precision character; the audit trail catches what used to be silent failures.

Phase 1 — incident response + observability (PRs 1-13)

  • getOrders(100) → getOrders(100, "open") at 5 sites. Alpaca's default status was all, so a churn-heavy account's 100-row response was dominated by filled/cancelled noise — open buys fell off the page, the duplicate-order guard went blind, and 3 identical WDC limits stacked up.
  • PDT-rejected stop placement → new engine.unprotectedSymbols + UI banner. Same-day positions whose stop Alpaca rejects (40310100) used to look protected in the dashboard while the broker had no resting stop.
  • PDT-rejected exit cascade → EXIT_REJECTION_THRESHOLD = 5 + ENGINE_EXIT_SUPPRESSED audit + push notification. APP triggered stop_loss every minute for 60+ min, each rejected, with no escalation. Now suppressed after 5 rejections for 30 min.
  • Standalone stop-sync scheduler — stop-sync-scheduler.ts runs every 5 min independent of scan health. Previously syncBrokerStops only fired at scan tails; hung scans froze broker stops for the whole session.
  • Tactical-smart scan hang fix — TACTICAL_SCAN_SYMBOL_BUDGET_MS = 8min + TACTICAL_MAX_EXTERNAL_SYMBOLS = 50. Screener was feeding 500+ symbols to the active-management loop; at ~1s/symbol (Finnhub-rate-limited) scans took longer than the 15-min cadence and never completed.
  • brokerConnected set in startEngine + new setBrokerConnected helper centralizing transitions with diagnostic log. 96 false-positive broker_disconnect alerts in 24h before the fix.
  • PWA install fix — manifest start_url was redirecting to /login for unauth users; Chrome rejects 3xx start_urls. Changed to /login?source=pwa (200).
  • Take-profit graduation feature — MODE_GRADUATION_DEFAULT + shouldGraduateExit + promoteToGraduationFloor. At pos.takeProfit, lock pos.stopLoss to entry × 1.30 and hold until 2-of-3 weakness signals fire.
  • client_order_id idempotency — every Alpaca placeOrder sends a UUID. Network-hiccup retries can't double-fill anymore.
  • Long Market Value display fix — Alpaca's portfolio_value is an alias for equity; the trader page was showing the same number twice. Now reads long_market_value directly with margin-loan sub-line when cash is negative.
  • Admin per-user dashboard + drilldown — new /api/admin/user-performance + /dashboard/admin/users/[id]. Sortable table with stale-engine warning icons; drilldown shows full broker connection, engine state, performance metrics, daily P&L, last 50 trades, last 25 audit events.

Phase 2 — optimized mode Option 2 (PR 14)

User observation: tactical-smart producing big runners (DELL +42%, MU +37%) while optimized produced steadier, smaller positions. Root cause was the strategy frame, not the GA params themselves. Brought optimized to capability parity while preserving its distinct character.

  • Graduation enabled for optimized — GA-tuned takeProfitAtrMult becomes a graduation point, not a hard exit. Lets runners ride past training-window-fit exit levels.
  • Screener-fed universe — runScan now uses selectExternalSymbolsForTactical(engine.externalSignals, SCAN_UNIVERSE). Top-50 by confidence, BUY/STRONG_BUY only.
  • Swap-sell post-exit redeploy — new MODE_SWAP_SELL_DEFAULT + deferred-candidates list. When an exit fires during the per-symbol loop, freed slots get redeployed into the top deferred STRONG_BUYs same-scan.
  • Multi-objective GA fitness — excessReturn × sharpeMult × drawdownMult. Pushes the GA away from blow-up-risk param sets that score high on raw return alone.

Optimized retains: per-symbol GA-tuned params, fixed position sizing, finite hold periods. Tactical-smart keeps: inverse-vol weighting, 999-day hold, pair-wise swap-sell.

Phase 3 — audit-driven hardening (PR 16)

  • P0 #1: Graduation defeated by runExitCheck — the 1-min poll still hard-exited at takeProfit, defeating graduation. Now gated on getGraduationMode === "disabled".
  • P0 #2: Stop-sync scheduler hung-scan recovery — gate now checks scan age vs STALE_SCAN_OVERRIDE_MS and runs sync anyway when exceeded. Previously skipped forever when scans chronically hung.
  • P1 #3: Swap-sell missing gates — redeploy now respects cooldown (150 min), exposure cap, sector-concentration cap. All silently bypassed pre-fix.
  • P1 #4: GA fitness preferred losers — multipliers on negative returns inverted preference. Fix: skip multipliers when excessReturn ≤ 0.
  • P1 #5: GA drawdown gradient collapse — multipliers floored at 0.05; drawdown softened to 30% window. Was flat-0 at maxDrawdown ≥ 20%, killing GA gradient.

Phase 4 — backtest/optimizer parity + audit follow-ups (PR 17)

  • Backtester graduation parity — both runBacktest and portfolioBacktest now simulate the graduation gate. Without parity, GA tuned under hard-exit fitness while live engine treated takeProfit as graduation.
  • Backtester STRONG_BUY hardCap overshoot — BACKTEST_HARD_CAP_STRONG_BUY = 1.5 × BACKTEST_MAX_POSITIONS. Mirrors runScan.
  • Backtester confidence-based ranking — STRONG_BUYs ranked by confidence desc within signal type. Mirrors swap-sell's "deferred candidates sorted by confidence."
  • Engine reboot state-loss audit — autoStartIfNeeded writes ENGINE_STARTED audit row with note explaining "any PDT alerts in next 5 min are state rebuild, not new conditions."
  • Hung-scan orphan-promise diagnostic — runScanGuarded tracks generation numbers; when an orphan resolves after a newer scan started, logs warn with generation mismatch. Real concurrency fix deferred.
Net for the user: the trader page's "stop below entry" condition that triggered this marathon is now fixed end-to-end. The optimizer is tuning for the strategy frame the live engine actually runs. Three classes of silent failure (PDT-rejected stops, PDT-rejected exits, scan hangs) now surface as user-actionable alerts.

Deferred to future PRs (tracked in docs/future-ideas.md): hung-scan orphan-promise concurrency fix, engine-reboot state persistence, swap-sell live-engine integration test.

2026-05-13

Reliability fixes

Three targeted fixes from a duplicate-order incident on a single user (SNDK) + getOrders failure-mode tightening + journal v2 hook.

Scan re-entrancy guard

The scan scheduler previously used a bare setInterval(() => scanFn().catch()). When a scan took longer than the tick interval (slow broker, large universe), the next tick fired while the previous scan was still in flight. Both concurrent scans called client.getOrders() independently — and because Alpaca's orders endpoint has hundreds-of-ms eventual consistency, the second scan's pendingBuySymbols set frequently missed the first scan's order. Result: both scans passed the duplicate-buy guard and placed identical limit orders sub-second apart. User reported as "two SNDK buys at the same price/qty/age."

Fix: closure-local scanInFlight flag flipped before scanFn() and cleared in .finally(). .finally() guarantees the flag clears even if scanFn throws. Belt: a 10-minute stale-flag watchdog overrides the flag if for some reason it stayed set (process crash mid-promise, runtime weirdness) so a wedged engine self-recovers within two intraday ticks. Same guard applied to the 1-minute exit-check interval.

getOrders failure: now aborts scan

Previously a try { ... } catch {} silently swallowed errors fetching open orders. The scan continued with an empty pendingBuySymbols set — going blind on duplicate-order detection. Now all three BUY paths (runScan, runTacticalScan, runTacticalSmartScan) log a warning, push a user-visible error, and abort the BUY portion of the scan when getOrders fails. Exits + position-map sync already happened before the getOrders call, so the abort is safe for stop-loss management.

Journal v2 hook in reconciler

When reconcilePendingTrades transitions a row from PENDING to FILLED, it now also calls createAutoJournalStub() (fire-and-forget, never throws). Inserts a journal entry pre-filled with the trade mechanics (symbol, action, fill price, P&L, signal) plus leading questions ("Why am I taking this trade?" for entries, "What's the lesson?" for exits). Idempotent via the journal_auto_trade_uniq partial unique index (migration 0032) — re-runs no-op. User opens the journal page and fills in the WHY; blank-canvas friction removed.

2026-05-12

Marathon updates (Phases 1-4)

Post-launch hardening pass. Items here augment the engine ruleset's relevant sections; cross-references CLAUDE.md's 6-phase retrospective for commit SHAs.

Phase 1 — money bugs from UI-lie audit

  • canPlaceBuyOrder() is async + takes a fresh account snapshot. Refreshes the wash-sale symbol set before the wash-sale check; re-runs evaluatePdtState before the PDT check. A 2nd day-trade in a 15-min window or a same-scan losing-close-then-re-entry now correctly evaluates against live state instead of scan-boundary state.
  • Gate ordering inside canPlaceBuyOrder(): earnings blackout → sector exposure → wash-sale → PDT → daily notional → rate-limit. Cheapest checks first; the first reason found is what gets logged.
  • bootEquity re-snapshots at every new trading day across both remaining scan paths. The 50% equity-collapse tripwire stays calibrated as the account grows organically.
  • tripSafeguardHalt() writes halted=true to trader_daily_pnl immediately so the dashboard reflects halts on the next fetch.
  • Dashboard todayPnl response carries source + staleSeconds so the UI can render staleness honestly instead of silently mixing broker intraday with DB snapshot.

Phase 2 — frozen-value cleanup

  • syncPositionMapFromBroker() resets pos.peakPrice = currentPrice when broker qty drops > 5% (partial close — trail recalibrates from post-close size).
  • Strategy params refresh per sync — strategy edits propagate to existing positions instead of being frozen at entry-time values.
  • Take-profit recompute when strategy takeProfitPct changes — existing positions get the new target.

Phase 3 — live-trading safeguards

  • 5 capital circuit breakers: daily loss halt, consecutive losses halt, broker-unreachable halt, account-mismatch halt, equity-collapse halt. Every halt writes a hash-chained audit row.
  • Account-switch detection — broker account number + boot equity captured at startEngine(). Mid-session change → halt.
  • Order rate limit — 30 orders / 60s sliding window per engine. Prevents runaway loop scenarios.
  • Daily notional cap — rejects BUYs exceeding maxDailyNotionalPct × bootEquity.

Phase 4 — Phase 5 (personalized live protections)

  • §475(f) MTM election — self-attested via Trader → Tax election card. Disables wash-sale tracking when elected (MTM exempt from §1091).
  • Wash-sale protection — blocks BUYs on symbols with a losing exit within the last 31 calendar days. Symbol-level, not lot-level — over-conservative but simpler.
  • PDT protection — auto-detected from account.equity < $25,000. Blocks BUYs (not SELLs) when pdtVulnerable && daytradeCount >= 3.
